# Support Policy

## Current Status

Zuno has no supported public release. Use the repository only for design and development.

## Support Channels

Use a GitHub issue for a verified defect. Use a GitHub discussion for a design question. Use the
private security channel for a vulnerability.

Do not send credentials or customer data.

## Issue Information

Include:

- package name
- package version
- runtime and version
- provider environment
- expected result
- actual result
- minimal reproduction
- redacted request identifier

## Support Levels

- `official` receives maintainer support.
- `community` receives support from named community maintainers.
- `experimental` has no stability commitment.
- `deprecated` receives only security corrections during its notice period.

## Version Support

The project will publish a version support table with the first stable release. The table will
identify security and defect support periods.

## Provider Incidents

Provider outages can affect Zuno operations. Confirm the provider status before you report an
outage.

Include the provider request identifier when available. Do not include an access token.

## Service-Level Commitment

The open-source project has no service-level agreement. A separate commercial service can define an
agreement.
